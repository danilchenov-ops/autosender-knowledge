# Инструкция для каждого проекта/чата Claude

Вставить в инструкции проекта. **Короткий блок ниже — единственное, что нужно копировать.**
Сами правила не дублировать: они живут в `/opt/knowledge/AGENTS.md` и `rules.md`,
под git. Копия в настройках проекта — единственная, которая не под версионированием,
поэтому она протухает первой.

```
Проект ведётся через реестр /opt/knowledge на сервере 5.35.99.93 (MCP ropbot → ssh_run).

Первым делом в каждой сессии:
  cat /opt/knowledge/AGENTS.md
  cat /opt/knowledge/INDEX.md
  cat /opt/knowledge/projects/README.md
По теме задачи и ключевым словам из README выбери project-файл, прочитай его целиком
и скажи одной строкой, какой выбрал. Сначала блок «## СОСТОЯНИЕ НА <дата>» — это
актуальная картина, всё ниже — история. Блоку больше 14 дней — сперва перепиши его.

AGENTS.md главнее этой инструкции. В нём: зоны ответственности между Claude и Codex,
работа без веток, откуда брать дату, что делать при грязном git status.

После любых изменений — запись в /opt/knowledge/changelog.md, затем git commit
И ОБЯЗАТЕЛЬНО git push. Без push копия на GitHub отстаёт и второй агент видит старое.

Код Виртуального РОПа — /opt/ropbot, там свой AGENTS.md: прочитать до правки кода.
```

Таблица проектов и ключевых слов — `projects/README.md`.

**Проект «Виртуальный менеджер Андрей» (autosender-vm):** своя инструкция для проекта Claude —
`/opt/vm/docs/project-instructions.md` (читать → ветка → PR → merge → деплой → changelog). Вставлять её,
а не общий блок выше.
