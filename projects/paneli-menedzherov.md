# Панели менеджеров и РОПа

Веб-страницы с картиной по менеджеру, каждому своя ссылка. Начато 22.08.2026.
Пилот — одна страница «Качество разговоров» на Пономаре, дальше расширяем
и по людям, и по содержанию.

## Зачем

Всё, что посчитано — правила идеального менеджера, скоринг заявок, оценка
разговоров — лежит в базе и раз в неделю уходит таблицей в Телеграм. Таблица
в мессенджере не годится для ежедневной работы: её нельзя открыть, когда нужно,
и в неё не влезает список конкретных разговоров со ссылками в CRM.

Решение Тимофея 22.08: свой сервер, постоянные ссылки, у каждого менеджера своя.
Отвергнуто: публикация артефактом на claude.ai (страница — снимок, обновление
только перепубликацией, доступ через расшаривание аккаунта).

## Как устроено

    Postgres ──► web/dash.py ──► /opt/ropbot/web/d/<токен>/index.html ──► nginx

- **Токены** — таблица `dash_tokens` (`token`, `kind`, `portal_user_id`, `page`,
  `active`, `note`, `created_at`, `built_at`). Ссылка вида
  `/d/b17904628c068aa12d7aee5f4e9b1679/`, 32 hex-символа, `openssl rand -hex 16`.
- **Генератор** — `/opt/ropbot/web/dash.py`. **В образ не запечён**: подаётся
  в контейнер через stdin (`docker exec -i ropbot-collector-1 python - --token X
  < web/dash.py`). Поэтому правка страницы не требует `docker compose build`
  и не роняет расшифровку. Обратная сторона — файл живёт вне `app/`, при переносе
  проекта его легко забыть.
- **Сборка** — `/opt/ropbot/web/build.sh`, крон `*/15` под `flock -n`
  (машина загружена, прогоны не должны наслаиваться). Запись атомарная:
  во временный файл, потом `mv`.
- **Отдача** — nginx, сайт `/etc/nginx/sites-available/dash`, корень
  `/opt/ropbot/web`. Каталог `/d/` без листинга, `/` отдаёт 404, `robots.txt`
  запрещает всё, заголовки `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`,
  `Cache-Control: no-store`. В ufw открыты 80 и 443.
- **Данные наружу не ходят**: страница статическая, база в интернет не смотрит.

## Страница «Качество разговоров» (готова 22.08.2026)

Считается по карточке эталонного скрипта (`app/card.py`), окно 14 дней:

| Блок | Что показывает |
|---|---|
| Балл | средний `card_score` 0–100, среднее по отделу, изменение за 7 дней к предыдущим 7 |
| Плитки | сколько разговоров разобрано, доля сильных (≥50) и слабых (<25) |
| Пять критериев | доля разговоров, где критерий зачтён; штрих — среднее по отделу; вес критерия |
| По дням | средний балл за день, пунктир — среднее по отделу, таблица под спойлером |
| Разговоры | последние 40: дата, длительность, балл, что зачлось и чего нет, следующий шаг, резюме, ссылка в Битрикс |
| Как это считается | оговорки, в том числе «не для премий» |

Правила счёта: непригодные номера отброшены (правило 1), отдел — только
`managers.department = '[5]'`, время местное (Влд).

Телефон клиента маскируется (`+7 (904) ***-**-78`), полная карточка — по ссылке
в Битрикс, где и так нужна авторизация.

Цифры сверены отдельным запросом 22.08: 212 разговоров, балл 33,6, сильных 25%,
слабых 37%, отдел 33,9 — сходится со страницей.

## HTTPS: упёрлись в чужой лимит

`certbot --nginx` на `danilchenov.fvds.ru` вернул
`too many certificates (50) already issued for "fvds.ru" in the last 168h`.
Имя — поддомен общего домена FirstVDS, недельный лимит Let's Encrypt считается
на `fvds.ru` и выбирается всеми клиентами хостера. Это не разовая неудача:
то же самое будет при каждом продлении.

Что сделано: `/opt/ropbot/web/certbot_retry.sh`, крон `17 * * * *` под `flock` —
ловит свободное окно и **сам снимает себя с крона** после успеха.

Запасной вариант Buypass Go SSL отпал: `api.buypass.com` не резолвится через
DNS-серверы хостера (через 8.8.8.8 резолвится). Лезть в `/etc/systemd/resolved.conf`
на боевой машине ради обходного пути не стали.

**Правильное решение — поддомен своего домена**, например `rop.autosender.ru`
A-записью на 5.35.99.93. Тогда лимит свой, продление автоматическое, и ссылка
выглядит прилично для менеджеров. Ждём решения Тимофея.

Пока сертификата нет, ссылка отдаётся по HTTP. **После выпуска сертификата
токен пилота сменить** — он какое-то время ходил открытым текстом.

## Осталось

1. **Поддомен `rop.autosender.ru`** (или подтверждение, что живём на fvds.ru).
2. **Сводная страница РОПа** — все менеджеры строками, показатели столбцами,
   подсветка отклонений от нормы.
3. **Остальные пять менеджеров** — по токену каждому, содержание то же.
4. **Другие блоки на страницу:** шесть правил идеального менеджера
   (`v_manager_ideal`), очередь заявок дня по классам ⚡/★/♛, динамика по неделям
   (`v_manager_weekly`), результат по вызревшим лидам (`v_manager_result`).
5. **Как раздавать ссылки.** Сейчас — переслать вручную. Аккуратнее: команда
   в @ironbossAS_bot, бот уже знает сотрудников и выдаёт ссылку тому, кто просит.
6. **Договориться, как этим пользуются.** Страница задумана для планёрок
   и отбора записей на прослушивание. Если её начнут читать как KPI — она
   врёт: каждый третий проигранный разговор набирает больше 50 баллов.

## Осторожность

- Окно 14 дней, у Владимира за это время может не набраться выборки —
  страница переживёт пустоту, но выводы по ней делать нельзя.
- Карточка есть только у разговоров от 90 секунд за последние три недели.
  Короткие звонки и недозвоны в балл не входят вообще.
- Сравнение с отделом — среднее по шести менеджерам, а не норма. Норма для
  критерия «следующий шаг» — 68% (уровень выигранных разговоров), а не 22%.
