# slepok-menedzherov

Количественный слепок работы менеджеров: ежедневный снимок одинаковых
параметров по каждому менеджеру → эталон среди своих → разрывы → цена разрывов
в сделках. Начато 25.08.2026, постановка Тимофея (промт «слепок → эталон →
разрывы → влияние»). Решение Тимофея 25.08: снимок обновляется **каждый день**,
с сегодняшнего дня (в исходной постановке была неделя).

## Что уже работает (этап 2 — сделан 25.08.2026)

### Таблица `manager_snapshot`

Миграция `app/sql/018_snapshot.sql`. Ключ: `snap_date × portal_user_id ×
period × param × grade`. `portal_user_id = 0` — весь отдел. Периоды:
`7d`, `30d` (окна заканчиваются началом дня снимка по Влд — покрывают полные
прошедшие сутки), `mom` — моментальные (только у сегодняшнего снимка),
`mat` — вызревшие заявки 45–135 дней.

Страты `grade`: `all` / `A` / `B` / `C` / `D` / `X` (нет данных) / `std` —
прямая стандартизация: взвешено по составу классов **отдела** в том же окне,
веса перенормируются на страты, где менеджер представлен (порог ≥50% потока).
Для медиан std — взвешенное среднее медиан страт (приближение).

### Скрипт `app/snapshot.py`

В образ не запечён, подаётся через stdin. Крон ежедневно:
`15 23 * * *` MSK (= 06:15 Влд) → `/var/log/ropbot/snapshot.log`.
Ключи: `--date YYYY-MM-DD`, `--retro` (понедельники с 08.06.2026).

Правила счёта соблюдены: только mobile, без PARTNER, окно звонков по
`phone_e164` от **первичной карточки номера**; скорость/настойчивость/
плотность/растянутость/конверсия — только по первичным карточкам (дубли
не в вину); первый отклик в рабочих минутах (`work_minutes`, 10:00–19:00 Влд);
дефект `work_minutes(a,NULL)=0` обойдён фильтром «контакт был».

### Параметры

Блок А (заявки/звонки/CRM), страты по классам:
- **C1** первый отклик, раб. мин (медиана, только заявки с контактом) · **C2** доля ≤15 раб. мин
- **H1** попытки за 72 ч от первого неотвеченного (медиана; когорта сдвинута на 3 дня — окно полное) · **H2** брошено: ≤1 попытка и ни одного разговора, %
- **P1** исходящих за первые 3 дня (среднее) · **P2** дозвон ≥30 с за 3 дня, %
- **R1** разговоры в ≥3 разных дня за 14 дней, % · **R2** ≥3 разговоров, % (когорта −14 дней)
- **GI1** часов до первого статуса после NEW (медиана, по всем карточкам) · **GI2** закрыто в F без единого разговора по номеру, % · **GI3** просроченных лидов с делом CRM_TODO (шт, `mom`, определение = TODO_SQL панелей: distinct lead, end_time::date < сегодня)
- **REZ** конверсия вызревших первичных карточек 45–135 дней в S (по клиенту: любой лид номера в S), период `mat`

Блок Б (разговоры, `grade='all'`):
- **G1** длительность первого содержательного разговора ≥60 с (медиана, сек) · **G2** балл карточки этого разговора (данные с 20.08)
- **D1** конкретный следующий шаг (`next_step_specific`), % разобранных · **D2** выполненные договорённости: исходящий не позже конца обещанного дня, % (due_date в окне)
- **GO1** реакция на корону ♛: рабочих часов от `first_crown_at` до следующего исходящего (медиана; короны без последующего звонка не входят — помнить)

Блок Т (портрет «кто ведёт разговор», `grade='all'`):
- **T1** индекс инициативы 0–100 (вопросы менеджера > клиента; шаг предложил менеджер; завершил менеджер) — по новым полям
- **T2** доля прожатых: уступка без встречного обязательства (`concession='бесплатно'`)
- **T3** отработка первого отказа (`first_pushback_handled` / `first_pushback`)
- **T4** индекс техник 0–5→% (квалификация до цены, выгода к словам клиента, цена с обоснованием, договор-регулярка, дата и время)
- Прокси до накопления новых полей: **T1p** (`next_step_proposed`), **T3p** (`objections_handled` при возражениях), **T4p** (pain + date_time + регулярки договора и квалификации по расшифровке)

### Расширение промта разборщика (25.08.2026)

(~со 25.08 18:00 Влд). Стоимость: было 2293 in / 320 out токенов

~1 мин на перезапуск, `up -d --scale asr=2`). Побочно вступил в силу

`--retro`: понедельники 08.06–24.08 + 25.08, 13 дат, 7 268 строк. Глубина
честная: когорты звонков с июня (правило 6), статусы с 27.04, карточки

Первый снимок сверен пятью независимыми SQL — всё сошлось точно:
C1/C2 Жернова 7d (83 заявки, 187,4 мин, 32,5%), H1/H2 отдела (156, 2, 12,8%),
REZ Попова (1561, 2,434%), GI3 (Пономарь 307, Симаненко 255 — совпало
с TODO_SQL панелей), D1 отдела (573, 21,5%).

Грабли по пути: (1) `GROUPING SETS ((uid),())` без grade в группировке —
GroupingError; (2) пустое окно даёт строку `()` с count=0 → деление на ноль,
всюду `NULLIF`; (3) образ collector был старее llm — `b24_summary` не было,
тест патча гонять через `docker compose run --rm --no-deps -T llm`;
(4) сервис llm перехватывает перевыставленную задачу очереди за секунды —
для теста останавливать контейнер.

2. **Разрывы и цена**: топ-3 значимых отставания на менеджера, консервативная

   и не для премий. Требование Тимофея: красивый визуал, круговые диаграммы.
4. Через месяц — замер сдвига параметров и конверсии, отчёт Тимофею.

## Осторожность

- Классы A/B/C/D есть с 01.08 → ретро-снимки раньше августа только `all`/`X`;
  классовый разрез REZ появится к октябрю (классы + 45 дней вызревания).
- T-параметры до накопления новых полей — только прокси (T1p/T3p/T4p),
  внутривыборочные регулярки по моно-расшифровке без ролей.
- GO1 не видит корон, после которых не звонили вообще — заниженная строгость.
- Снимки за прошлые даты считаются сегодняшним знанием статусов (REZ, GI2):
  ретро — не «как выглядело тогда», а «как было на самом деле».

### Эталон: Жернов

Попов — номинальный лидер конверсии, но его процесс — антиобразец: 32,8%
недозвонных заявок брошено после 0–1 звонка (выброс, у следующего 15%), 27,2%
закрытий без единого разговора, худшая плотность (П1 1,51). Результат вопреки
процессу — копировать нечего. Жернов: устойчивый топ-2 конверсии в обоих
периодах + лучшая плотность (П1 2,01, П3 4,5%), хорошая настойчивость
(Н2 7,9%), топ по следующему шагу (Д1 24,3%) и выполнению договорённостей
(Д2 56,4%). По каждому параметру на вкладке эталон свой — лучший менеджер
этого параметра.

### Цена разрывов (константы этапа 4)

Консервативно: половина фактической разницы конверсий вне выборки, вилка
×0,25…×1. П3: Δconv = 6,5 п.п. (holdout) → в цене 3,25 п.п. на первичную
заявку. Н3: Δconv = 4,15 п.п. (независимая когорта июня–июля) → в цене
2,1 п.п. на недозвонную заявку. Д1/Т4 — разрыв показывается без цены
(карточки молодые, честной Δ конверсий нет). Формула: заявок в окне 30д ×
(доля эталона − доля менеджера) × Δconv_цены. Пометка о неопределённости
обязательна: самоотбор не вычищен, истинную цену даст только эксперимент
№1 идеальной сделки.

## Этапы 4–5 — разрывы, цена, вкладка «Эталон» (25.08.2026, сделано)

**Вкладка РОПа «Эталон»** (`etalon.html`, page_etalon в web/dash.py, собирается
в bundle all раз в 15 минут). Круговой визуал: каждый параметр — кружок-донат,
заливка = близость к эталону параметра (лучшему в отделе, n≥10), цвет
зелёный/жёлтый/красный (≥85% / ≥55% / ниже), синий полный — сам эталон
параметра; стрелка ▲▼ — динамика к снимку недельной давности с поправкой на
направление. Три блока: «Рычаги результата» (П3, Н3, Д1, Т4-прокси),
«Дисциплина» (С1, Н2, Ги2, Ги3, Д2, Го1), «Следствия интереса и результат»
(Р2, Г1, Рез). Внизу — «Разрывы и цена»: карточка на менеджера, топ-3 разрыва
по весам этапа 3, цена в сделках/мес с осторожной вилкой (П3 и Н3), у Д1/Т4
честная пометка «карточкам меньше месяца». Константы ET_* сверху блока.

**Дашборд менеджера**: блок «Три точки роста» (mgr_gaps_block) — личные топ-3
разрыва простым языком «у Николая — 9,2%, у тебя — 7,2%», без рейтинга,
с пометкой «не для премий». Показывается только менеджерам из WORKING
(активный токен) — Владимира (15079) на страницах нет, как и раньше.

Первые цены разрывов скромные и честные: 0,1–0,6 сделки/мес на разрыв
(доли 5+ звонков у всех 3–5%, потолок эталона близко). Крупных халявных
резервов в этих параметрах сейчас нет — рост будет от сдвига всего отдела,
не от подтягивания одного отстающего.

Проверка визуала: страница отрендерена в Chromium (1500px, светлая и тёмная
темы) — сетка не едет, донаты читаются, «мало данных» и «нет данных»
отображаются серым.

Патч: web/etalon_patch.py (идемпотентные якоря), бэкап web/dash.py.bak-etalon.
