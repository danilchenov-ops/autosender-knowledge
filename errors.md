## 09.09.2026 — Предположение записано как факт (лимиты Я-3/Я-6)
Что: по расходу одного дня сделал вывод «лимиты применились» и записал в реестр без пометки «предположение».
Почему: настройки ТК через API не видны; расход понедельника не доказательство; подтверждения Тимофея не было.
Исправлено: запись в reklama.md от 09.09; правило — любая настройка ТК фиксируется только по подтверждению
Тимофея или по недельному расходу (не дневному), с пометкой источника.

## 09.09.2026 — открытые лиды включали удалённые в CRM
Что: все счётчики по открытым лидам (панель «Сейчас», очереди, Внимание)
считали лиды, которых в Битриксе уже нет — до 25 штук, у менеджера до +6.
Почему: инкрементальный sync по DATE_MODIFY не видит удаления.
Исправлено: sweep_deleted_leads в crm_sync (semantic 'D'), см. changelog 09.09.
При анализе цифр по открытым лидам до 09.09 помнить о завышении.

## 11.09.2026 — Просадку Китая приписал креативу, не проверив целостность фида
Что: 5–7 дней объяснял рост CPC/падение показов сменой картинок на коллаж; рекомендовал откат. Причина
оказалась в баге фида (2 авто вместо полного каталога).
Почему: проверял только метрики кампании и контрольную группу; не проверил число активных объявлений/товаров.
Как исправлено: вердикт аннулирован; в протокол замера смены фида добавлен шаг 0 — «число товаров в фиде
и объявлений с показами до/после» (в интерфейсе ТК или отчёт по объявлениям). Правило: резкое падение
показов при смене фида — сначала проверить сам фид, потом креатив.

## 15.09.2026 — «ТК работают в режиме по ценности конверсий» — записано без проверки интерфейса
Что: с 21.08 в реестре и в ответах Тимофею утверждалось, что товарные кампании оптимизируются по ценности
целей с весом договора ×6 относительно заявки. Скриншот блока «Целевые действия» 15.09 показал: колонки
ценности нет, режим — максимум количества целевых действий, все пять целей равновесны.
Почему: вывод перенесён с тестовой кампании 713613428 (где ценности действительно задавались вручную) на
товарные, настройки которых через API не читаются. Нарушено правило «вывод о настройке, сделанный по API
или по аналогии, проверять в интерфейсе до рекомендаций».
Цена: три недели рекомендаций вокруг ценности цели (40 000 → 85 000) адресовались механизму, который в этих
кампаниях не работает. Реальная проблема — договор составляет 0,7 % сигнала обучения, чат Venoo — 20 %.
Как исправлено: запись в projects/reklama.md от 15.09, вопрос 49 закрыт, рекомендация по Метрике снята.

## 15.09.2026 — Настройки одной ТК обобщены на все: «ценности не заданы» оказалось верно не везде
Что: по скриншоту кампании с бюджетом 100 000 («Максимум целевых действий», «Без ограничений», колонки цены
нет) сделан вывод, что у ВСЕХ товарных кампаний цены целей не заданы и режим — по количеству. На его основе
построен расчёт «доля договора в сигнале 0,7–1,24 %» и вся логика развесовки. Тимофей показал, что в Я-2
цены уже стояли: 1000/1000/1500/5000/1500, то есть режим «Средняя за неделю» с развесовкой.
Почему: один скриншот принят за состояние аккаунта; настройки ТК через API не читаются, а руками проверена
была одна кампания. Это повтор ошибки от 15.09 про «режим по ценности» — тот же корень: вывод по аналогии
вместо проверки каждой кампании.
Цена: расчёты эффекта («в 11 раз больше вес договора») считались от неверной базы. Реальный сдвиг для Я-2:
вес договора 4,4 % → 13,5 % (в 3 раза), Venoo 24,9 % → 10,1 %. Направление верное, масштаб завышен втрое.
Как исправлено: запись в projects/reklama.md от 15.09 с пересчётом от фактической базы; в план внесена
обязательная ручная проверка режима и цен по каждой ТК до любых дальнейших правок и до объявления
контрольной группы.
