# Правила ведения реестра (вставляется в инструкции каждого проекта Claude)

Реестр /opt/knowledge — единый источник правды. Читается через ropbot ssh_run.
Нарушение правил ниже приводит к дрейфу: чаты принимают решения по устаревшей картине.

## Чтение
1. Перед работой: cat /opt/knowledge/INDEX.md и cat /opt/knowledge/projects/README.md.
   По теме задачи и ключевым словам из README выбрать project-файл (один или два) и прочитать:
   cat /opt/knowledge/projects/<выбранный>.md. Сказать пользователю одной строкой, какой файл выбран.
   В файле сначала блок «## СОСТОЯНИЕ НА <дата>» — это правда; всё ниже — история.
   Если блока нет или ему больше 14 дней — сначала переписать его, потом работать.
   Ни один файл не подходит — правило 11.
2. Числа из реестра — с базисом (НДС, атрибуция, период, источник). Без базиса число не использовать.

## Запись
3. После любого изменения (сервер, настройки, решение, вывод) — запись в /opt/knowledge/changelog.md
   с датой и git commit в /opt/knowledge. Формат: что было → что сделали → что проверить и когда.
4. Блок «СОСТОЯНИЕ» переписывается целиком на каждом чекпоинте, 30–50 строк: что есть сейчас,
   действующие решения, ближайшие контрольные точки с датами.
5. Один факт — одно место. Id целей, токены-указатели, доступы — только integrations.md;
   серверы и крон — servers.md / services.md. В проекте — ссылка, не копия.
6. Различать пометки: «внесено Тимофеем», «рекомендовано Claude», «гипотеза». Не смешивать.
7. Открытые вопросы — в open-questions.md. Закрытый не удалять: под ним «→ ЗАКРЫТО дата: чем».
8. Ошибка анализа (неверный базис, неполная выборка, не та атрибуция) — в /opt/knowledge/errors.md:
   что, почему, как исправлено. Файл общий для всех проектов; читать его перед выводами по цифрам.
9. Сырые выгрузки, длинные таблицы, логи — не в реестр. Класть в /root/out/ и ссылаться.
10. Секреты в реестр не писать никогда — только где лежат.

## Новый проект
11. Создать projects/<имя-латиницей>.md из projects/_template.md. Добавить строку в
    projects/README.md и prompt-import.md — иначе другие чаты его не найдут.
12. Первой записью — цель и одна измеримая метрика успеха с числом. Без метрики проект не заводить.
13. Перед созданием проверить пересечение с существующими файлами: если тема на 70 % уже лежит
    в другом — писать туда. Признак дубля: один id кампании / скрипт / таблица в двух проектах.

## Разветвление и сжатие
14. Появился самостоятельный второй контур — новый файл с первого дня, в родителе строка
    «вынесено в <файл>». Не ждать, пока перемешается.
15. Лимит project-файла — 800 строк. Сверх — хронология старше 30 дней уходит в
    projects/archive/<имя>-до-<дата>.md, в основном файле остаётся ссылка.
16. Чекпоинты — по решениям, не по дням. Замер без решения — в changelog, не в проект.
17. Завершённый проект: в «СОСТОЯНИИ» — «ЗАВЕРШЁН дата, итог: …», файл в projects/archive/,
    строка в README остаётся с пометкой.

## Контроль
18. Понедельник 09:00 kbcheck.sh шлёт Тимофею в бот сводку дрейфа. Команда «сверь реестр»
    в любом чате — Claude закрывает пункты сводки.
