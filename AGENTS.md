# AGENTS.md — реестр Autosender

Файл читают все AI-агенты (Claude, Codex и следующие). Правила общие для всех.

Полный регламент ведения реестра — `rules.md`, 18 правил. **Он главнее этого файла:**
при расхождении верить `rules.md`. Здесь только то, что касается git и работы двух агентов.

## Что это

`/opt/knowledge` на сервере 5.35.99.93 — единый источник правды по серверам, сервисам,
интеграциям, решениям и проектам Autosender: реклама (Директ, Метрика), Виртуальный РОП,
Битрикс24, страница подписки, посевы, звонки, панели менеджеров.

Сайт autosender.ru сюда **не входит**: у него своя база знаний `/opt/claude-kb`
на 83.136.235.210, свой `AGENTS.md` и свой репозиторий на GitLab.

## С чего начинать сессию

1. `git pull`.
2. `cat INDEX.md`, затем `cat projects/README.md`.
3. По теме и ключевым словам выбрать project-файл, прочитать его.
   Одной строкой сказать Тимофею, какой файл выбран.
4. Первый блок `## СОСТОЯНИЕ НА <дата>` — актуальная картина. Всё ниже — история.
   Блоку больше 14 дней — сначала переписать его, потом работать.

## Единственная пишущая копия — на сервере

Писать в реестр можно **только** в `/opt/knowledge` на 5.35.99.93.

- **Claude** — напрямую, он работает на этом сервере.
- **Codex** — через MCP `ropbot` (`ssh_run`, `write_file`). Локальный клон на маке держит
  **только для чтения**: быстро грепать контекст без ssh. Из клона не коммитить и не пушить.

Причина: в реестр пишет не только человек. Крон в 06:00 кладёт снимки в `audit/`,
`kbcheck.sh` по понедельникам дописывает сводку. Две пишущие копии разъедутся за сутки.

## Коммиты

- **Веток нет. Только `main`, прямой коммит.** PR и ревью здесь не нужны — это реестр, а не код.
- Один коммит = одно осмысленное изменение. Сразу после коммита — `git push`.
- Сообщения на русском, как уже принято в истории: `checkpoint 13.09: ...`, `audit ...`.
- Авторство подписывать явно, по умолчанию в репо стоит `claude-autosender`:

  Claude: `git commit -m "..."`
  Codex:  `git -c user.name=codex-autosender -c user.email=danilchenov@gmail.com commit -m "..."`

- `git push --force` запрещён обоим. История реестра — доказательная база, переписывать нельзя.

## Когда работаем одновременно

- Перед правкой — `git status`. Дерево грязное = кто-то уже внутри:
  остановиться и спросить Тимофея, а не продолжать поверх.
- Не запускать двух агентов на одну задачу. Это надёжнее любых правил в файле.
- `git pull --rebase` перед push, если push отклонён.

## Зоны ответственности

Веток нет, значит единственная защита от столкновений — не оказываться в одном месте.
По умолчанию:

- **Claude** — реестр, цифры, аналитика, выводы по кампаниям и менеджерам,
  блоки «СОСТОЯНИЕ», решения.
- **Codex** — код: `/opt/ropbot`, скрипты, панели, починки.

Это не запрет, а умолчание. Зашёл в чужую зону — скажи Тимофею, зачем,
и сначала проверь `git status`.

## Даты

Дату брать **с сервера**, командой `date`. Сервер живёт в Europe/Moscow.
Не подставлять дату из своего окружения и не пересчитывать во владивостокское время:
13.09 19:20 по серверу — это 13.09, а не 14.09. Из-за этого записи в `changelog.md`
и `decisions.md` расползаются по двум часовым поясам и ломают хронологию.

## Секреты

- Правило 10: ни паролей, ни токенов в реестре — только указатели, где лежат.
- `.gitignore` закрывает `.kbtoken`, `.env*`, ключи. Не обходить его через `git add -f`.
- Токены сервисов лежат в `/opt/ropbot/.env`. Читать оттуда, в ответы не выводить.

## Что сюда не кладём

- Сырые выгрузки, длинные таблицы, логи — в `/root/out/`, в реестре только ссылка (правило 9).
- Код — в репозиторий `autosender-ropbot`, не сюда.
- Отчёты о проверках и черновики — в `changelog.md`, не отдельными файлами.

## Если непонятно

Не угадывать. Спросить Тимофея — особенно про цифры, прод и деньги.
